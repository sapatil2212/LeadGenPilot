# Gemini-grounded outreach template drafting

The change replaces the Templates page’s hardcoded starter records with an unsaved AI draft assembled from the current tenant’s profile, catalogue, facts, and retrieved document excerpts. The draft opens in the existing editor for human review, but approval remains browser-local and disconnected from the active campaign workflow. Provider and output enforcement also fall short of the UI’s Gemini-specific, safe-template contract. **Watch for:** **confirmed** browser-only persistence bypasses workspace sharing and permission enforcement; **confirmed** campaigns ignore saved templates; **confirmed** existing user templates are orphaned; **confirmed** Gemini can silently fall back; **confirmed** channel and placeholder constraints are not enforced; **likely** document prompt injection can become accepted plain-text claims; **confirmed** `{{name}}` resolves to the company; **confirmed** no focused tests cover the feature.

**Verdict**: NEEDS_CHANGES

## High-level view

**Confirmed:** generation requires `MANAGE_TEMPLATES`, but saving writes directly to a workspace-suffixed localStorage key. Teammates and the server cannot see those records, while users without the permission can still create or alter them locally.

**Confirmed:** the canonical campaign panel neither loads nor submits template selections, and campaign generation always creates fresh AI or rule-based copy. The editor’s “ready for use in campaigns” confirmation is therefore false for the primary campaign path.

**Confirmed:** Gemini is first in a fallback chain, not mandatory. Another configured provider can produce a draft while the generation UI still describes the operation as Gemini-backed.

**Confirmed:** the validator is not channel-aware and does not enforce plain text, URLs, word limits, or save-time edits. **Likely:** because uploaded text is interpolated raw and injection defense is prompt-only, malicious document instructions can still induce unsupported claims that satisfy the string validator.

**Confirmed:** the old unsuffixed storage key has no migration, so existing user-created templates disappear. The supported `{{name}}` placeholder also maps to `lead.businessName`, and unsupported placeholders added during review remain literal.

**Confirmed:** typecheck and the existing 977 tests pass, but none covers the new endpoint, provider constraint, empty context, adversarial documents, output validator, storage migration, or campaign handoff.

<details><summary>Details</summary>

## Browser-local approval bypasses workspace persistence and authorization

`EmailTemplates` writes the complete reviewed template to `localStorage` under `leadfinder_email_templates_v3:${workspaceId}` (`src/EmailTemplates.tsx:89,141-163,229-252`), and `loadOutreachTemplates` reads that browser key (`src/outreachTemplates.ts:19,45-53`). There is no template model or CRUD API.

This is a **confirmed** delivery defect: records are unavailable to another workspace member or device, disappear with browser storage, remain readable after browser-side membership loss, and cannot be loaded by server campaign generation. `MANAGE_TEMPLATES` protects only AI generation; a user without it can still create, edit, duplicate, or delete local templates. Persist reviewed templates through tenant-scoped server CRUD guarded by `MANAGE_TEMPLATES`, then resolve every consumer through the authenticated workspace.

## Reviewed campaigns never consume reviewed templates

The active Generate Campaign form posts only lead source, channels, and `useAi`; it never loads templates or sends `templateIds` (`src/features/CampaignPanel.tsx:525-552`). Although the campaign request and row can hold template IDs, `generateCampaign` never resolves them and always calls `generateAICopy` or `generateOutreachCopy` (`src/campaign/campaignService.ts:38-42,110-112,175-190`).

This is a **confirmed** end-to-end break. The editor says a save is ready for campaigns, but `/app/campaigns` cannot select or use it; the routing change aliases `/app/outreach` to that panel, leaving local-template loading only in legacy lead-outreach code (`src/App.tsx:1118-1121,1793-1796`). Add tenant template selection, resolve ownership server-side, snapshot/compile the selected template into pending messages, and do not substitute a hardcoded/rule-based starter when a reviewed template was selected.

## Existing user templates are orphaned by workspace keying

The editor now reads only `leadfinder_email_templates_v3:${workspaceId}` and treats absence as empty (`src/EmailTemplates.tsx:89,141-159`); the shared loader does the same (`src/outreachTemplates.ts:45-53`). No code reads the previous unsuffixed key.

This is a **confirmed** data-visibility regression: every existing user-created template disappears with the removed samples. Add a one-time ownership-safe migration or explicit import/claim flow rather than assigning unscoped records to an arbitrary tenant.

## Gemini preference is not a Gemini guarantee

`generateTemplateDraft` supplies `preferredProvider: "gemini"` (`src/business/templateGenerator.ts:156-164`), but the shared AI layer retains every configured fallback and iterates through that chain (`src/ai/aiService.ts:86-98,176-190`).

This is a **confirmed** mismatch with the explicit Gemini requirement. Use an exact-provider option or constrained Gemini service path; if Gemini is unavailable, return the existing 503 instead of silently changing vendors.

## Untrusted knowledge and output are not constrained at the delivery boundary

Document titles and contents are interpolated raw into the user message immediately before channel instructions (`src/prompts/outreachTemplateDraft.ts:179-224`). The validator requires only non-empty `name` and `bodyText`, strips four tag names, filters model-produced placeholders, and applies character caps (`src/prompts/outreachTemplateDraft.ts:60-115`). It accepts other HTML such as links/images, contact details or URLs, subjects over 80 characters, and email/WhatsApp bodies over the promised word limits. Save-time edits bypass it (`src/EmailTemplates.tsx:229-242,320-445`).

The missing deterministic constraints are **confirmed**. Successful prompt injection through a malicious document is **likely** because an injected unsupported claim remains an accepted string despite the grounding instruction. Serialize excerpts as explicitly untrusted data, validate against the requested channel after generation, reject markup and forbidden URL/contact content, repeat validation at save/dispatch, and test adversarial excerpts.

## `{{name}}` produces wrong personalization and unknown edits leak through

The new contract supports `{{name}}` (`src/prompts/outreachTemplateDraft.ts:60-69,192-200`), and generated drafts can default to `Hi {{name}},` (`src/business/templateGenerator.ts:183-185`). The compiler maps it to `lead.businessName` and preserves unknown tokens (`src/outreachTemplates.ts:75-85`).

This is a **confirmed** output defect: “Hi {{name}}” becomes “Hi Acme Ltd,” while an unsupported placeholder added during review can reach outbound copy verbatim. Map a real recipient-name field or remove `{{name}}`, and reject unresolved placeholders before review or dispatch.

## Core generation and handoff behavior has no regression coverage

No test references `/api/business/template-draft`, `generateTemplateDraft`, `outreachTemplateDraft`, or the suffixed storage key. `npm run typecheck` and `npm run test:run` pass (38 files, 977 tests), but they do not exercise this feature.

This is a **confirmed** delivery gap. Add route/service tests for tenant isolation, permissions, exact Gemini selection, empty-context/provider errors; validator tests for channel limits, markup, placeholders, and adversarial excerpts; and an integration test proving one workspace’s saved template is compiled by its campaign and inaccessible to another.
